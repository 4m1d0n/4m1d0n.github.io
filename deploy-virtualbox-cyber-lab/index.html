Deploying a Cybersecurity Lab on VirtualBox

May 12, 2025 · 5 min read
warning

This post is a work in progress — updates coming soon!

This blog kicks off a series dedicated to building a complete cybersecurity home lab on VirtualBox — designed to support both red teaming and blue teaming activities. From attacking vulnerable services to detecting malicious behavior with a SIEM, this lab provides a self-contained environment to practice real-world scenarios.

Throughout this project, we deploy and configure:

  • Kali Linux: our attacker and administration machine
  • pfSense: a firewall/router to segment our lab into realistic network zones
  • GOAD (Active Directory lab): to simulate internal corporate infrastructure
  • A vulnerable web server in the DMZ
  • Splunk (or ELK): for centralized log collection and detection engineering
  • OpenVAS/Nessus: to simulate vulnerability scans and management

Each system is deployed on VirtualBox and connected through isolated internal networks, allowing realistic simulation of internal, external, and DMZ scenarios. The lab is entirely offline and open-source friendly (except where noted, like Nessus Essentials).

This post gives a full architectural overview and deployment philosophy, with links to step-by-step guides for each component.

Building a VirtualBox-Based Cybersecurity Home Lab

Setting up a dedicated cybersecurity lab is one of the most effective ways to sharpen your skills, experiment safely, and document your progress. Whether you're preparing for certifications, building a red/blue team mindset, or simply exploring new tools, having your own lab environment offers freedom and depth unmatched by online platforms.

In this blog series, I document the complete setup of my VirtualBox-based cyber range, focused on pentesting, blue teaming (SOC), and vulnerability operations (VOC). Everything is hosted locally and uses free, open-source tools, making it highly accessible and reproducible.

💡 If you're just looking to jump straight into configuring a core component, check out: Building a Security Home Lab in VirtualBox

Why Build a Home Lab?​

There are tons of platforms out there (HTB, TryHackMe, etc.), but building your own lab helps you:

  • Develop practical skills in real-world architectures.
  • Learn how network segmentation, routing, and firewalling work.
  • Create controlled environments to test malware, exploits, detections, and defenses.
  • Practice the attack–detect–defend triad used in many professional environments.
  • Gain hands-on exposure with SIEM, vulnerability scanners, Active Directory, and DMZ setups.

This lab is designed to mirror enterprise-grade complexity while staying manageable for a single host machine using VirtualBox.

Lab Architecture Overview​

Here's a high-level view of the lab’s architecture:

ZoneDescriptionTools/VMs
Internal NetworkSimulates a corporate LAN.GOAD (Active Directory), workstations
DMZExposed web server to simulate public-facing applications.Vulnerable Linux web app
Attacker ZoneWhere attacks are launched and tests are run.Kali Linux
Routing/FirewallControls traffic between zones.pfSense
SOC (Monitoring)Central log aggregation and detection.ELK Stack (ElasticSearch, Logstash, Kibana)
VOC (Vuln Management)Detect and manage vulnerabilities.OpenVAS or similar

All virtual machines are interconnected through VirtualBox's internal networks, with pfSense acting as the router and firewall between zones. Each network is segmented, offering a realistic testbed for attacks and defenses.

Project Structure​

The full deployment is structured in stages, with each post documenting:

  • The deployment of a specific component.
  • Key configuration steps.
  • How each component fits into the bigger picture.
  • Preparation for a final Attack / Detect / Defend demo with CVEs.

Deployment Roadmap:​

  1. Install and configure pfSense with all necessary interfaces
  2. Install Kali Linux as the attack/admin machine
  3. Configure pfSense firewall rules
  4. Deploy a vulnerable Linux web server in the DMZ
  5. Install GOAD (Active Directory simulation)
  6. Install and configure the ELK stack for log centralization
  7. Set up log forwarders and visibility tools
  8. Deploy OpenVAS for vulnerability scanning
  9. Launch real-world CVE exploits, detect them via logs, and respond using blue team techniques

Tools and Technologies​

This lab uses only free, open-source tools:

  • VirtualBox (VMs)
  • pfSense (firewall/router)
  • Kali Linux (attacker)
  • GOAD (Active Directory lab)
  • Ubuntu/Debian (vulnerable apps, web server)
  • ELK Stack (SIEM)
  • OpenVAS (VOC)

Who Is This For?​

This series is designed for:

  • Security enthusiasts wanting to go beyond CTFs.
  • Pentesters looking to simulate internal/external assessments.
  • Blue teamers and SOC analysts aiming to improve detection engineering.
  • Students prepping for certs like OSCP, CPTS, or Blue Team certs.
  • Anyone building a portfolio to land a first job in cybersecurity.
