🔧 What is Virtio-Net?​

  • Virtio is a virtualization standard for network and disk device drivers.

  • It's designed to provide high-performance I/O between guest and host by reducing overhead.

✅ Advantages of Virtio-Net (Paravirtualized)​

  1. 🧠 Performance

    • Virtio drivers are lighter and closer to the hypervisor’s abstraction, so data flows with much less CPU usage.

    • Higher throughput and lower latency compared to emulated NICs.

  2. 🔄 Lower Overhead

    • Emulated NICs (like Intel PRO/1000) try to mimic real hardware, which adds unnecessary CPU cycles.

    • Virtio bypasses this by exposing a virtual interface optimized for virtualization.

  3. 📦 Better Packet Handling

    • More efficient in terms of packet I/O, useful when simulating large volumes of network traffic (e.g., Snort, Zeek, packet captures).

  4. 🧪 Realism in Labs

    • If you're testing logging, detection, or IDS systems, virtio gives you closer-to-realistic traffic flow without dropping packets due to CPU limitations.

  5. 💾 Lower Disk & Memory Impact

    • Less stress on system resources compared to traditional emulated devices.

❗️ When not to use it​

  • If you're using a guest OS that doesn't support virtio drivers out of the box (e.g., older versions of Windows), you might have issues.

  • In that case, you’d need to install the virtio drivers manually during OS setup.

🧪 In Your SOC/VOC Lab​

Since you're simulating attack/detection chains with tools like ELK, Zeek, or Suricata, virtio-net is perfect. It makes sure your lab isn’t bottlenecked by networking performance, especially when sending logs or simulating attacks across multiple machines.

TL;DR:
Use virtio-net unless you have OS compatibility issues. It's faster, lighter, and built specifically for virtualized environments.

Adding Another Interface to pfSense in VirtualBox

In the VirtualBox GUI, there are no more than 4 tabs to configure network adapters on any VM. However, you can actually add up to 8 network interfaces on any VM.

Using the VirtualBox CLI

In order to add additional interfaces to pfSense, we will have to use the VirtualBox CLI -- vboxmanage.exe.

Shutdown the pfSense VM and run these commands:

# Notice that my commands specify the number 5 in the options
    # --nic5, --nictype5, --intnet5, --cableconnected5
.\VBoxManage.exe modifyvm "Homelab Firewall - PfSense" --nic5 intnet
.\VBoxManage.exe modifyvm "Homelab Firewall - PfSense" --nictype5 virtio
.\VBoxManage.exe modifyvm "Homelab Firewall - PfSense" --intnet5 "Homelab - SOC"
.\VBoxManage.exe modifyvm "Homelab Firewall - PfSense" --cableconnected5 on

Start the pfSense VM and the first thing you’ll notice, is that I still only have 4 interfaces. This is because the new interface is not up yet.

This is because you may be using a laptop and if you connect to public wireless, then your pfSense web console would be open to the others on that network.
