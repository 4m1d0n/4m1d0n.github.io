Deploying a pfSense VM for Our VirtualBox-Based Cyber Lab

In this module, we’ll set up a pfSense firewall virtual machine in VirtualBox to segment and secure the networks within our home lab.

info

This page is part of a broader series on creating a cybersecurity lab with VirtualBox. Click here to return to the main project description page.

Downloading pfSense​

warning

pfSense serves as the NAT router and firewall for the lab environment, so it must be the first virtual machine to start. Once pfSense is up and running, you can launch the rest of your VMs.

Whether you're building a lab in the cloud (GCP, AWS, Azure, ...) or on-premises, it's essential to design your network upfront. Be sure to account for future scalability, as redesigning the network later is far more challenging than planning it properly from the start. Refer to the diagram in the main project description.

note

Recently, Netgate began requiring users to create an account and provide personal information to download pfSense CE ISO images—a change we're not particularly excited about. While this appears to be a measure to prevent misuse of pfSense Plus by third-party vendors, we'll show you how to download the ISO in a way that respects your privacy.

Adding a new Virtual Machine in VirtualBox​

On VirtualBox, click on "New" to add a new virtual machine

Select a folder of your choosing to store your homelab's VMs files and make sure you select the downloaded PfSense ISO file in "ISO Image".

Depending on your infrastructure, pfSense doesn't require extensive resources, but it's always a good idea to allocate a reasonable amount to ensure smooth performance.

Adjust the memory and processor settings according to your system capacity

Leave the default 16GB, it is enough for PfSense

Click Finish

Right click on the new VM, choose "Setting..."

In the "System" tab, move "Hard Disk" above "Optical" and disable "Floppy" in the boot order

Disable the audio controller under the "Audio" tab, since it's not needed for pfSense

Under "USB", uncheck "Enable USB Controller" to disable unnecessary hardware

Setting up Network Interfaces on the VM​

One of the most important steps ! Configuring the network interfaces.

For this lab, we will be using a paravirtualized network adapters (virtio-net) in VirtualBox (also available in other hypervisors).

What is a virtio-net Adapter type ?​

  • Virtio is a virtualization standard for network and disk device drivers.
  • It's designed to provide high-performance I/O between guest and host by reducing overhead.
Advantages of Virtio-Net (Paravirtualized)​
  1. Performance
    • Virtio drivers are lighter and closer to the hypervisor’s abstraction, so data flows with much less CPU usage.
    • Higher throughput and lower latency compared to emulated NICs.
  2. Lower Overhead
    • Emulated NICs (like Intel PRO/1000) try to mimic real hardware, which adds unnecessary CPU cycles.
    • Virtio bypasses this by exposing a virtual interface optimized for virtualization.
  3. Better Packet Handling
    • More efficient in terms of packet I/O, useful when simulating large volumes of network traffic (e.g., Snort, Zeek, packet captures).
  4. Realism in Labs
    • If you're testing logging, detection, or IDS systems, virtio gives you closer-to-realistic traffic flow without dropping packets due to CPU limitations.
  5. Lower Disk & Memory Impact
    • Less stress on system resources compared to traditional emulated devices.
warning

If you're using a guest OS that doesn't support virtio drivers out of the box (e.g., older versions of Windows), you might have issues. In that case, you’d need to install the virtio drivers manually during OS setup.

In our lab, since we are simulating attack/detection chains with tools like ELK or Suricata, virtio-net is perfect. It makes sure our lab isn’t bottlenecked by networking performance, especially when sending logs or simulating attacks across multiple machines.

On the "Network" menu, we add the following interfaces :

Adapter 1 : WAN interface for Internet connectivity, we chose "Bridged Adapter" instead of NAT

Under "Network", select "Paravirtualized Network (virtio-net)" as the adapter type. For Adapter 1, it will be our WAN, so we will attach it to "Bridged Adapter"

Adapter 2 : LAN interface for the network management & attack simulations

Select "Paravirtualized Network (virtio-net)" as the adapter type. Set Adapter 2 to "Internal Network" for LAN configuration. We named it "Homelab - LAN", which will be used for network management and attacker simulation

Select "Paravirtualized Network (virtio-net)" as the adapter type. Set Adapter 3 to "Internal Network" for the Isolated LAN. We named it "Homelab - Isolated", to be used as our DMZ

Select "Paravirtualized Network (virtio-net)" as the adapter type. Set Adapter 4 to "Internal Network" for the Active Directory

Configure the LAN interface​

Here, we configure the LAN interface by assigning static IP address and enabling the DHCP server:

On the pfSense console menu, select option 2 to Set interface(s) IP address.

  • Choose the interface number corresponding to the LAN (in this case, 2).
  • When prompted, decline DHCP for the LAN interface by typing n.
  • Enter the desired static IP address (10.100.0.1) and subnet mask bit count (24 for a /24 subnet).
  • Leave the upstream gateway blank by pressing ENTER.
  • Disable IPv6 configuration by typing n.
  • Enable the DHCP server on LAN by typing y, then specify the DHCP range (start: 10.100.0.11, end: 10.100.0.100).
  • Enable the DHCP server on LAN by typing y, then specify the DHCP range (start: 10.100.0.11, end: 10.100.0.100).
  • Answer n to reverting to HTTP as the webConfiguraor protocol.

A Quick Note on Firewall Configuration

In this guide, we’re intentionally not exposing the pfSense web interface to the WAN.

This precaution is especially important if you're using a laptop that may connect to public Wi-Fi networks—doing so could leave your pfSense web console accessible to others on the same network.

Instead, we’ll use our Kali VM to manage and configure firewall rules locally in the next steps.
