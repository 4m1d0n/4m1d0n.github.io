5. Installing GOAD in a VirtualBox Lab

What is GOAD?​

GOAD is a pentest active directory LAB project. The purpose of this lab is to give pentesters a vulnerable Active directory environment ready to use to practice usual attack techniques.

It provides a ready-to-use environment with multiple Windows domain controllers, member servers, and an Ubuntu attacker box — all provisioned via Vagrant and running in VirtualBox.

System Requirements​

GOAD is quite resource-intensive. You should allocate:

VariantVMsCPU + RAMStorageUse Case
GOAD (Full)58 vCPU + 24 GB RAM~115 GBFull forest, trusts, and labs
GOAD-Light34 vCPU + 20 GB RAM~20 GBLighter scenarios
GOAD-Mini22–4 vCPU + 16 GB~16 GBMinimal lab (DC + client only)
SCCM4Similar to full~MoreSCCM-focused use cases
warning

Disk space: Windows Server images consume ~14–22 GB each. Ensure at least 115 GB free on your disk to prevent provisioning failures.

warning

RAM: Ensure your host has enough RAM to run all VMs. If you're short on memory, consider GOAD-Mini or GOAD-Light.

Prerequisites​

You'll need the following tools installed:

  • VirtualBox
  • Vagrant
  • Windows Subsystem for Linux (WSL)
  • Git

We recommend WSL (Debian) for smoother compatibility with the GOAD installation scripts.

# Install WSL with Debian from PowerShell
wsl --install -d Debian

Installing GOAD​

We will clone the official GOAD repository and run the provisioning scripts.

sudo apt update && sudo apt install git
mkdir -p /mnt/{YourDisk}/Homelab/
cd /mnt/{YourDisk}/Homelab/
git clone https://github.com/Orange-Cyberdefense/GOAD.git
cd GOAD
./goad.sh

You’ll then be prompted to choose a lab variant:

set_lab GOAD           # or GOAD-Light, GOAD-Mini
set_ip_range 10.88.88  # Your preferred subnet
set_provider virtualbox
install
provision_lab

Configuring VirtualBox Networking​

To integrate GOAD with the rest of your lab (e.g., pfSense, Wazuh), you’ll want to ensure the GOAD VMs are on the "Homelab - AD" internal network. Use this PowerShell snippet:

$VBoxManage = "C:\Program Files\Oracle\VirtualBox\VBoxManage.exe"
$vmNames = @("GOAD-DC01", "GOAD-DC02", "GOAD-DC03", "GOAD-SRV02", "GOAD-SRV03")
$networkName = "Homelab - AD"
$adapterType = "82540EM" # Intel PRO/1000 MT
$promiscuousMode = "deny"

foreach ($vm in $vmNames) {
  & "$VBoxManage" modifyvm $vm --nic1 none
  & "$VBoxManage" modifyvm $vm --nic2 intnet
  & "$VBoxManage" modifyvm $vm --intnet2 "$networkName"
  & "$VBoxManage" modifyvm $vm --nictype2 $adapterType
  & "$VBoxManage" modifyvm $vm --cableconnected2 on
  & "$VBoxManage" modifyvm $vm --nicpromisc2 $promiscuousMode
}

Figure 1: All GOAD VMs are bridged to the internal network 'Homelab - AD'.

Troubleshooting Common Issues​

VMs Freezing​

If VMs freeze or the playbook hangs, try:

  • Restarting all VMs
  • Unchecking Nested Paging
  • Enabling Legacy Paravirtualization

Figure 2: Disabling Nested Paging in VirtualBox settings.

WinRM Authentication Failed​

Edit the Vagrantfile to allow plaintext WinRM (only for lab use!):

config.winrm.transport = "plaintext"
config.winrm.basic_auth_only = true

Figure 3: WinRM plaintext configuration for provisioning to succeed.

Updating the Lab or Restarting Playbooks​

To re-run a specific playbook (e.g., if provisioning failed on ad-child_domain.yml):

provision_lab_from ad-child_domain.yml

You can find the list of available playbooks here: 👉 https://github.com/Orange-Cyberdefense/GOAD/blob/main/playbooks.yml
